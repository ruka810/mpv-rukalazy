# mpv-rukalazy 使用教程

本教程覆盖：安装、必装依赖、可选组件、配置、快捷键、迁移与排错。
只想尽快看片：完成 **1.1 ~ 1.3** 即可。

---

## 1. 安装与首次运行

### 1.1 系统要求

- Windows 10 / 11，64 位
- 7-Zip（解压分卷用，Windows 自带解压不支持）
- 解压后约 5 GB 空间（含 VapourSynth CUDA 运行库与滤镜模型）
- 可选：NVIDIA 显卡（补帧、超分、Whisper CUDA）

### 1.2 解压位置

Release 里的完整包受 GitHub 单文件 2 GiB 限制，拆成了 `mpv-rukalazy-v1.0.0.7z.001`、`.002`… 分卷。请把**所有分卷**下载到同一个文件夹，只右键 `.001` 用 7-Zip 解压，其余分卷会自动读取（不要改名、不要单独解压）。

解压到**普通可写目录**，例如：

```
D:\mpv-rukalazy\
```

注意：

- 不要放 `C:\Program Files`（脚本需要写日志和缓存）。
- 路径里可以有中文和空格，但不要放在 OneDrive 等会同步/占位的目录。
- 整个文件夹可以随意改名、换盘；换位置后按 [1.5](#15-移动或换机后必须重做的事) 重跑几个注册脚本即可。

### 1.3 必装依赖：ffmpeg

`ffmpeg` 不在压缩包内。安装步骤：

1. 下载 <https://www.gyan.dev/ffmpeg/builds/> 的 `release-essentials`。
2. 解压到例如 `C:\ffmpeg`，把 `C:\ffmpeg\bin` 加入系统 `PATH`。
3. 新开命令行执行：

   ```powershell
   ffmpeg -version
   ```

能输出版本号即可。

用到的场景：Whisper 音频采集、片段导出、RIFE 离线渲染。

### 1.4 文件关联与启动模式

双击 `mpv.exe` 即可启动。想让视频文件默认用它打开：

双击 `installer\mpv-register.bat`（会弹 UAC，点“是”）。取消关联：

```powershell
installer\mpv-unregister.bat
```

`installer\` 里还有三种独立启动配置：

| 文件 | 用途 |
| --- | --- |
| `mpv-纯净模式.bat` | 不加载着色器/滤镜，排查问题时用 |
| `mpv-测试模式.bat` | 加载 `mpv-test.conf` |
| `mpv-跑分模式.bat` | 固定的跑分/对比配置 |

### 1.5 移动或换机后必须重做的事

注册表里记录的是**绝对路径**，所以移动文件夹或复制到另一台电脑后，需要重新运行：

1. `installer\mpv-register.bat`（文件关联）
2. `portable_config\tools\install_bridge_scheme.ps1`（`bilibili-mpv://` 协议）
3. `portable_config\tools\chrome_cookie_bridge\install_native_host.ps1`（Cookie 桥）
4. Chrome 里重新加载一次扩展（`chrome://extensions` → 该扩展 → 重新加载）

## 2. 本地播放与常用操作

- 拖入文件 / 双击文件即可播放。
- 鼠标移到窗口底部弹出 uosc 控制栏；**右键**打开功能菜单（轨道、画质、弹幕、章节等）。
- `Ctrl+i` 查看全部快捷键。
- 播放进度、音量等会自动记住。
- 字幕颜色：uosc 控制栏的字幕颜色按钮（调色板或输入色号），选择后自动写入 `mpv.conf`，重启仍保留。

## 3. Chrome Cookie 桥（可选但推荐）

作用：让 mpv / yt-dlp 使用你 **Chrome 里已登录的 B 站、YouTube cookies**，用于：

- B 站 AI 字幕
- 会员/付费内容
- 直播弹幕发送
- YouTube 部分需要登录的视频

Cookie 由 Chrome 扩展读取后经本机命名管道交给桥；桥会为 yt-dlp 写出一份本机 cookie 文件（见文末“隐私”），不上传。

### 3.1 加载扩展

1. 确认存在：
   `portable_config\tools\chrome_cookie_bridge\publish_v13\mpv-cookie-bridge.exe`
2. 打开 Chrome，地址栏输入 `chrome://extensions`。
3. 右上角打开「开发者模式」。
4. 点「加载已解压的扩展程序」，选择目录：

   ```
   portable_config\tools\chrome_cookie_bridge\extension
   ```

5. 扩展列表里应出现 **mpv Chrome Cookie Bridge**。
   （manifest 里固定了 key，所以扩展 ID 始终是 `gikjlcfdnjgmdbdnefmknkpndmkfdlhf`。）

### 3.2 注册本机消息主机

在项目目录打开 PowerShell：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\portable_config\tools\chrome_cookie_bridge\install_native_host.ps1"
```

看到 `Native host registered for extension ...` 即成功。
它会写入 `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.mpv_lazy.cookie_bridge`，并把主机清单指向当前目录的 exe。

> 用 Edge 的话，需要把同一个键再建到
> `HKCU\Software\Microsoft\Edge\NativeMessagingHosts\com.mpv_lazy.cookie_bridge`，值同样指向
> `portable_config\tools\chrome_cookie_bridge\com.mpv_lazy.cookie_bridge.json`。

### 3.3 验证

1. Chrome 登录 B 站。
2. 打开一个 B 站视频，用 mpv 播放（直接粘贴链接，或用下一节的浏览器投递）。
3. 按 `q`：如果该视频有 AI 字幕，应直接显示；没有则回退 Whisper。

## 4. 浏览器「在 mpv 播放」（可选）

作用：在 B 站页面把解析出的 CDN 直链直接投递到**新开的 mpv 窗口**，并自动加载弹幕。

需要三样东西：油猴脚本、自定义协议、本地桥。

### 4.1 安装油猴脚本

1. 给 Chrome 安装 [Tampermonkey](https://www.tampermonkey.net/)。
2. 新建脚本，把 `portable_config\tools\bilibili_parse_relay.user.js` 的内容整个粘贴进去并保存。
3. 脚本会匹配 `www.bilibili.com/video|bangumi|cheese|list|festival`。

### 4.2 注册 bilibili-mpv:// 协议

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\portable_config\tools\install_bridge_scheme.ps1"
```

写入的是 `HKCU\Software\Classes\bilibili-mpv`，不需要管理员。

### 4.3 启动本地桥

本地桥监听 `127.0.0.1:8322`，必须常驻：

```powershell
# 方式一：双击
portable_config\tools\bilibili_parse_bridge.bat

# 方式二：命令行
pythonw.exe portable_config\tools\bilibili_parse_bridge.py
```

> mpv 启动时也会自动拉起桥，但浏览器先点按钮时桥可能还没运行；脚本会尝试用
> `bilibili-mpv://start` 自动拉起，第一次 Chrome 会弹「打开应用？」——勾选“始终允许”。

### 4.4 使用

1. 打开 B 站视频页，等待 injahow 解析面板出现直链。
2. 点面板里的 **「在 mpv 播放」**。
3. 会新开一个 mpv 窗口播放，`d` 可开关弹幕。

按钮置灰表示解析还没完成；没有任何提示通常表示投递成功（设计如此）。失败才会有错误提示。

## 5. Whisper 实时字幕（可选）

当 B 站视频**没有 AI 字幕**时，按 `q` 会回退到本地 Whisper 识别。
需要自己准备 whisper.cpp 的 CUDA 版本和模型（不随包分发）。

### 5.1 获取程序与模型

1. 从 <https://github.com/ggerganov/whisper.cpp/releases> 下载 Windows CUDA 包
   （文件名类似 `whisper-cublas-12.x-bin-x64.zip`）。
2. 解压后确认有 `whisper-server.exe`、`ggml-cuda.dll`、`cublas64_12.dll` 等。
3. 下载模型：
   <https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo-q5_0.bin>

### 5.2 放置位置

任选一种（按顺序查找）：

1. 在 `portable_config/script-opts.conf` 里指定：

   ```ini
   script-opts-append = whisper_realtime-whisper_root=D:\whisper
   ```

2. 放入包内：

   ```
   <包目录>\whisper\whisper-server.exe
   <包目录>\whisper\models\ggml-large-v3-turbo-q5_0.bin
   ```

3. 放入当前盘符根目录：

   ```
   D:\whisper\whisper-server.exe
   D:\whisper\models\ggml-large-v3-turbo-q5_0.bin
   ```

### 5.3 注意

- 需要 NVIDIA 显卡与驱动；CPU 版本能跑但实时性很差。
- 需要 `ffmpeg` 在 `PATH` 中。
- 按 `q` 关闭字幕会同时结束识别；切换文件会自动清理。
- 翻译用 `w` 开关，不影响原始字幕显示。

## 6. 代理与在线视频

`portable_config/mpv.conf` 默认：

```ini
ytdl-raw-options=proxy=http://127.0.0.1:10809
```

处理方式：

| 情况 | 做法 |
| --- | --- |
| Clash 端口就是 10809 | 不动 |
| 其他端口 | 改成你的端口 |
| 不要代理 | 删除或注释该行 |

不处理的话，YouTube / B 站联网解析会因为连不上代理而失败。

更新解析器：

```powershell
.\yt-dlp.exe -U
```

> 站点改版后如果突然解析失败，优先更新 yt-dlp。

## 8. 配置文件说明

| 文件 | 说明 |
| --- | --- |
| `portable_config/mpv.conf` | 主配置：硬件解码、GPU API、字幕字体、代理、截图目录等 |
| `portable_config/profiles.conf` | 条件配置：按分辨率、帧率、HDR 等自动套用 |
| `portable_config/input_uosc.conf` | 快捷键映射 |
| `portable_config/menu.conf` | 右键菜单项 |
| `portable_config/script-opts.conf` | 脚本参数（见下） |
| `portable_config/scripts/uosc/` | uosc 界面与扩展菜单 |

`script-opts.conf` 常用项：

```ini
# yt-dlp 包装器路径：相对路径按本文件所在目录解析，换盘不用改
script-opts-append = ytdl_hook-ytdl_path=tools/chrome_cookie_bridge/publish_v13/mpv-cookie-bridge.exe

# 弹幕默认值（百分比）
script-opts-append = bilibili_danmaku-opacity=100
script-opts-append = bilibili_danmaku-area=100
script-opts-append = bilibili_danmaku-font_size=100

# Whisper 目录（不写则自动查找，见第 5 节）
# script-opts-append = whisper_realtime-whisper_root=D:\whisper
```

修改配置后必须**重启 mpv**。编码使用 UTF-8（无 BOM），换行 LF 或 CRLF 均可。

## 9. 故障排查

| 现象 | 处理 |
| --- | --- |
| 双击 `mpv.exe` 没反应 | 用 `mpv.com` 启动看报错；检查杀毒软件、目录写权限 |
| 网页链接打不开 | 检查代理端口；`yt-dlp.exe -U` |
| 提示找不到 yt-dlp | 确认 `portable_config\tools\chrome_cookie_bridge\publish_v13\mpv-cookie-bridge.exe` 存在 |
| B 站 AI 字幕取不到 | Chrome 登录 B 站 + Cookie 桥已注册；刷新页面重试 |
| 按 `w` 提示“已是中文” | 正常：中文不翻译 |
| 弹幕不显示 | 确认是 B 站视频/直播；按 `d` 开启；直播未开播时无弹幕 |
| 弹幕字号/透明度不对 | `Ctrl+d` 重置，或删除 `%APPDATA%\bilibili_danmaku_state.conf` |
| 补帧/超分无效或崩溃 | 需要 NVIDIA；更新驱动；显存不足时降低设置 |
| 投递按钮没有出现 | 油猴脚本未生效/未匹配页面；刷新页面 |
| 投递按钮置灰 | 解析面板尚未解析完成 |
| 点击投递无反应 | 桥没运行：双击 `bilibili_parse_bridge.bat`；仍失败则删除 `tools\bilibili_parse_bridge.lock` 后重试 |
| 移动目录后投递失效 | 重跑协议注册与 Cookie 桥注册脚本，重新加载扩展 |
| Whisper 按 `q` 无反应 | 检查 `whisper-server.exe`、模型、ffmpeg；看 `mpv.com` 输出 |
| 字幕颜色改完没保存 | 确认 `portable_config/mpv.conf` 可写 |

日志位置：

- 投递桥：`portable_config\tools\bilibili_parse_bridge.log`
- 截取/渲染：`portable_config\tools\capture_tools_error.log`

## 10. 更新、卸载与迁移

### 更新

- 配置/脚本：用新 Release 覆盖 `portable_config/`（先备份你自己的 `mpv.conf`、`saved-props.json`）。
- yt-dlp：`yt-dlp.exe -U`。
- 不要覆盖 `portable_config/_cache/`，删掉也无妨（会自动重建）。

### 卸载

1. `installer\mpv-unregister.bat`
2. `powershell -File ".\portable_config\tools\install_bridge_scheme.ps1"` 的反向操作：
   ```powershell
   Remove-Item 'HKCU:\Software\Classes\bilibili-mpv' -Recurse
   ```
3. 删除 `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.mpv_lazy.cookie_bridge`
4. Chrome 里移除扩展，删除整个文件夹。

### 迁移到另一台电脑

1. 复制整个目录到新机器（任意盘符、任意目录均可）。
2. 安装 ffmpeg（可选 Node.js / Whisper）。
3. 重跑第 [1.5](#15-移动或换机后必须重做的事) 节的四个步骤。
4. 按新机器的代理端口修改 `mpv.conf`。

## 隐私

- 本项目不联网上报任何数据。
- Cookie 由 Chrome 扩展经本机命名管道传给桥；为兼容 yt-dlp，桥会写出 `portable_config\_cache\cookies\yt+bilibili.txt`。该文件仅存于本机，删除 `_cache` 即可清除。
- 运行数据（缓存、播放记录、日志）都在本机目录内，已在 `.gitignore` 中排除。
